# Контракт работы с Cursor Agent

Этот файл обязателен для каждого существенного изменения.

## Роли

Cursor:
- исследует текущий код;
- реализует ровно согласованный scope;
- пишет и запускает тесты;
- сообщает результат;
- коммитит только завершённую логическую порцию работы.

Архитектурный ревью выполняется отдельно человеком/внешним ревьюером.
Cursor не должен самовольно расширять scope следующей версии.

## Перед началом каждой задачи

1. Прочитать:
   - `README.md`
   - `docs/ROADMAP.md`
   - `docs/ARCHITECTURE.md`
   - применимые `.cursor/rules/*.mdc`.
2. Проверить `git status`.
3. Кратко перечислить:
   - что меняется;
   - что не меняется;
   - критерии готовности.
4. Для задачи, затрагивающей много файлов или архитектуру, сначала использовать Plan Mode.
5. Не начинать соседнюю версию Roadmap без явной команды.

## Во время работы

- Не переписывать рабочий код без причины.
- Не менять API/контракт молча.
- Не добавлять тяжёлые dependency без обоснования.
- Не отключать lint/test/typecheck ради зелёной сборки.
- Не снижать покрытие критической математики.
- Не прятать ошибки за `any`, `@ts-ignore`, пустыми catch.
- Не класть секреты, токены, cookies, ключи, credentials.
- Не выполнять force push.
- Не merge в `main`.
- Не удалять историю git.
- Все UI тексты пользователю — на русском.
- Имена типов/функций/файлов/переменных — на английском.

## Git

Ветка:
`feature/v0-X-short-name`

Коммиты:
- `feat: ...`
- `fix: ...`
- `test: ...`
- `refactor: ...`
- `docs: ...`
- `chore: ...`

Одна законченная задача = один или несколько логичных commits.
Не коммитить build artifacts и секреты.

## Проверка перед завершением

Обязательно выполнить доступные команды:
- `npm run lint`
- `npm run typecheck`
- `npm test`
- `npm run build`

Для math/equity изменений дополнительно:
- scenario/golden tests;
- benchmark, если он уже существует.

## Формат финального ответа Cursor

Cursor обязан завершать каждую задачу строго таким блоком:

```text
STATUS: DONE | PARTIAL | BLOCKED

SCOPE:
- ...

CHANGED:
- файл — что изменено
- ...

TESTS:
- npm run lint: PASS/FAIL
- npm run typecheck: PASS/FAIL
- npm test: PASS/FAIL
- npm run build: PASS/FAIL

MATH/DOMAIN CHECKS:
- какие сценарии проверены
- если математика не затрагивалась: N/A

PERFORMANCE:
- что измерено
- если не измерялось: N/A

KNOWN ISSUES / RISKS:
- ...

GIT:
- branch:
- commit:
- pushed: YES/NO

NEXT RECOMMENDED STEP:
- одна следующая задача, без её реализации
```

## Если что-то сломалось

Не маскировать проблему.
Остановиться на минимальном воспроизводимом состоянии.
Привести:
- command;
- error;
- suspected root cause;
- files involved;
- что уже пробовали.

## Запрет на самоуверенные утверждения

Если recommendation engine пока rule-based, в коде, README и UI запрещены заявления:
- "GTO";
- "optimal";
- "solver-equivalent";
- "гарантированно правильное решение".

Допустимо:
- "рекомендация модели";
- "rule-based recommendation";
- "оценка на основе выбранного диапазона и текущих метрик".
